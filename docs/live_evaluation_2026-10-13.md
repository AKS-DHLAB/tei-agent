## 2. KNoTE 정답 대비 정량 평가 (6편, 41,200자)
- **입력:** KNoTE 본문에서 태그를 걷어낸 원문(문단 단위)
- **과정:** 자동 1차 태깅 → `rs`·`measure`·`time` 추천 수용 → 검증
- **제외:** few-shot 예시로 쓰인 3편(동백꽃·운수 좋은 날·혈의 누)은 평가에서 뺐습니다.
- **평가 대상:**
  - 감자, 메밀꽃 필 무렵, 무정(단편): 1차 결과를 보고 규칙을 고친 *튜닝셋*
  - 우리 동무를 위하여, 물, 향수: 규칙 수정 뒤 처음 돌린 *홀드아웃*

| 소요 시간 | 편당 62–81초 |

요소별 성능은 마이크로 평균입니다. 정확 일치는 시작과 끝 위치가 모두 같은 경우, 겹침은 위치가 일부라도 겹치는 경우를 셉니다.

### 수치를 읽을 때 유의할 점
- **정답 데이터의 관행 차이가 큽니다.**
  - KNoTE는 1인칭 서술자 '나'를 `persName`으로 태깅했습니다(「물」 한 편에서만 39회). TEI 관점에서는 대명사이므로 모델은 `rs`로 처리했고, 이것이 점수를 깎습니다.
  - '학교', '동네' 같은 일반명사를 `placeName`으로 태깅한 경우가 작품마다 들쭉날쭉합니다.
  - `measure`와 `date`의 경계 관행도 다릅니다(예: '두 평 칠 합', '한 달').
- **`rs` 재현율이 낮은 이유:** KNoTE의 `rs`는 대명사와 친족어까지 매우 촘촘합니다. 추천 수용 단계 한 번만으로는 다 잡지 못하고, 대화로 추가 지시해야 합니다.
- **후속 규칙의 효과:** 존칭 접미사(군·씨·님)를 이름 밖으로 빼는 규칙과 일반 장소명사를 `placeName`에서 제외하는 규칙을 추가한 뒤 2편을 다시 돌렸습니다(`examples/live/dev2/`).
  - 「향수」 `persName` 정확 F1: 0.24 → 0.69
  - 「우리 동무를 위하여」 `placeName` 예측 수: 86 → 40 (과잉 태깅이 절반으로 줄었으나 정답 14보다는 여전히 많음)
  - 이 2편은 이후 튜닝셋으로 분류합니다.

## 5. 실사용에서 발견해 고친 문제
| 문제 | 조치 |
|---|---|
| 장 번호 '1', '2'를 쪽번호 `<pb/>`로 바꾸며 **텍스트 삭제** | 분석 단계에서 쪽번호가 있다고 판단한 경우에만 숫자 삭제를 허용. 그 외에는 원문 보존 검사에서 실패 처리 |
| 대명사에 조사 포함 (`<rs>그의</rs>`) | 한국어 조사 분리 규칙을 모든 개체·지시 요소에 확대 적용 |
| 존칭 접미사 포함 (`우영 군`) | 접미사는 `persName` 밖에 두는 규칙 추가 |
| `@when="0000-03-23"` (XSD에는 0년이 없음) | `--03-23`으로 자동 변환하고 프롬프트에 명시 |
| `@quantity="열세"` (숫자가 아님) | 한국어·한자 수사를 아라비아 숫자로 변환. '몇' 같은 모호한 값은 제거 |
| 블록 안에 모델이 직접 `<div>`를 써서 중첩 div 발생 | 출력에서 자동으로 풀고 프롬프트로 금지 |
| 운문 희곡의 행 구분 소실 | 희곡·시는 줄바꿈을 보존해 블록을 나누도록 변경 |
| **메타데이터 추천이 엉뚱한 Wikidata ID를 '높은 확신'으로 제시** (김동인에게 Q485385, 실제로는 웨일스 메탈 밴드 Bullet for My Valentine) | 모델이 낸 식별자는 모두 제거하고 검증된 전거 검색으로만 넣도록 함 |
| 원문에 없는 서지 값(창작 1936년 등)을 모델이 '원문 근거'라고 표시 | 결정론적 대조 도입: 사실 항목의 값이 원문에 없으면 '검증 필요'로 표시하고, CLI 자동 적용에서 제외 |
| 태깅 중 질문이 영어로 나옴 | UI 언어(한국어)로 질문하도록 고정 |
